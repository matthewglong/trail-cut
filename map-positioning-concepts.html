Why this works

One large viewport reads as a viewfinder, not a thumbnail. The composition mode is the primary decision and lives in dedicated cards with mini-glyphs — no jargon to decode. Direct manipulation handles sit on the canvas itself, so the affordance is obvious.

Best for

Users who export to one ratio at a time and want maximum canvas to compose against. The "sync across ratios" toggle lets power users opt into propagating changes — the default is one-ratio-at-a-time editing.

Trade-off

You can't see what 9:16 looks like while editing 16:9 — the chip row shows applied state but not visuals. If side-by-side comparison matters, see Concept 02.

Why this works

All three exports visible at once. The active tile is unmistakable — chartreuse brackets, raised surface, "Editing" flag. Every control under the rail explicitly says "Editing 16:9" so there's no doubt about which preview is being changed.

Best for

Users who routinely export to all three ratios from the same project and want to see how each one reads. The dual sync toggles let you propagate just mode or just inset position selectively — no all-or-nothing.

Trade-off

Each preview is smaller than in Concept 01 — fine-positioning the inset is less precise. The unified rail also requires a click to switch between ratios for editing. Best paired with a "pop out to studio mode" link for detailed work.

Why this works

The preset library turns "what should this look like?" from a configuration problem into a selection problem. Most users land on a preset and ship; power users override in the right rail. The middle canvas stays focused on the one ratio you're tuning.

Best for

A growing app with recurring layout patterns. Once you have 5–10 presets, the modal becomes a fast picker rather than a configurator. Users can save their own presets (the "Save as preset" CTA at the bottom of the rail) — which compounds value over time.

Trade-off

Highest implementation cost. Requires a preset model, a library UI, and save/load flow — work that pays back only if presets get used. If most layouts end up bespoke, the library becomes overhead.
